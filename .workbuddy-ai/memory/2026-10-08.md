## edacode 独立交互式 agent —— Windows 适配 + MCP 接入

背景：`edacode` 是之前会话在 macOS 上写的独立 coding agent（从 01.py–17.py 学习 +
调研 codex/opencode/gemini-cli/qwen-code/ZCode 后重构）。搬到 Windows 后**测试全部 ERROR**，
核心原因是代码直接用了 POSIX 专属 API。

### 根因（3 个）
1. `storage.py` 会话锁 + `engine.py` Memory 文件锁 → `fcntl`（Windows 无此模块）
2. `processes.py` → `os.killpg` / `signal.SIGKILL` 不存在；`/bin/bash` 路径不存在
3. `shell=True` + `executable=bash` 在 Windows 上拼成 `bash /c ...`（bash 不认），命令必失败

### 改动
- 新增 `src/edacode/compat.py`：`IS_WINDOWS` / `lock_file` / `unlock_file` /
  `find_shell` / `shell_argv` / `kill_tree`。平台分支只在这一个文件里。
- `storage.py`：会话锁走 `lock_file`；`atomic_write` 在 Windows 覆盖只读目标前清只读属性。
- `engine.py`：`Memory.update` 走 `lock_file`（阻塞模式）。
- `processes.py`：`Popen` 改用 `shell_argv` 返回的 argv（有 bash 就 `[bash,"-c",cmd]`，
  否则回退 `shell=True`）；`kill_group` 走 `kill_tree`。
- `cli.py`：启动时 `sys.stdout/stderr.reconfigure(errors="replace")`，防 cp936 控制台打印崩溃。

### 新增能力：MCP stdio 客户端
- 新增 `src/edacode/mcp.py`：JSON-RPC over stdio，握手 `initialize` →
  `notifications/initialized` → `tools/list` → `tools/call`，协议版本 `2024-11-05`。
- 工具命名空间 `mcp__<server>__<tool>`；配置读工作区根 `mcp.json` 或 `.edacode/mcp.json`。
- 接入点：`Tools.external`（之前已预留）+ `Tools.definitions`；只读子 agent 不加载 MCP。
- 外部工具**不自动授权**，仍走 Policy（plan 拒绝 / ask·edit 审批 / auto 放行）。
- 单 server 失败只记录到 `/mcp`，不影响内置工具。新增 slash 命令 `/mcp`。

### 验证
- `PYTHONPATH=src python -m unittest discover -s tests -v` → **14 项全绿**（原 9 项 + 5 项新增）。
- 新增测试：shell 真执行、会话锁互斥、bash 可用性、MCP 端到端（真实子进程握手+调用）、
  MCP 失败不致命。
- 冒烟：`run.py --provider mock --json -p "列出当前文件"`、slash 命令流、`--help` 均正常。
- 清理 macOS 残留 `.DS_Store`（2 个）并加入 `.gitignore`。

### 未做（README「当前边界」已如实标注）
`10.py` 依赖任务图、`12.py` Cron、`13.py` 多队友 worktree、`15.py` 统一 harness、

- CLI 端到端：`/commands list` 列出项目+用户命令；`/review src/x.py` 展开含参数与文件注入；

- glob 实测：`**/*.py` 递归、`pkg/**/*` 含零层、`*.py` 仅顶层、`pkg/sub/*.py` 精确。

## 第七轮：opencode 风格终端界面

cmd / PowerShell / Windows Terminal / Git Bash / macOS / Linux 全稳，且可完整离线验证。

### 改动
- 新增 `src/edacode/ui.py`：
  - `Palette`（enabled=False 时所有码为空串 → 纯文本）；正文用 **16 色 ANSI**（跟随终端主题），

  - `visible_width()`：按 `east_asian_width` 算列宽（CJK=2），`strip()` 去 ANSI —— 保证彩色与纯文本**对齐一致**。
  - `supports_color()`：非 tty / `NO_COLOR` 返回 False；`enable_windows_ansi()` 用 ctypes 打开 Windows VT。

  输入提示改为彩色 `❯`；把原来的局部变量 `ui` 改名 `console`（与模块名冲突）。
